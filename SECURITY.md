# Политика безопасности

## Поддерживаемые версии

Проект активно поддерживается. Обновления безопасности применяются к последней версии в ветке `main`.

| Версия | Поддерживается |
| ------ | -------------- |
| 1.0.x  | ✅ Да          |

## Сообщение об уязвимости

Если вы обнаружили уязвимость в коде или зависимостях, **пожалуйста, не создавайте публичный Issue**. 

Используйте функцию [Private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) на вкладке **Security** в репозитории, либо напишите на контактный email (укажите ваш email, если хотите получать уведомления).

Мы постараемся ответить в течение 48 часов и выпустить патч как можно скорее.

## Об аудите зависимостей (`npm audit`)

При разработке вы можете заметить предупреждения `npm audit` (например, `moderate` или `low`). **Это не угроза для пользователей приложения.**

**Почему это безопасно:**
Это статическое офлайн-приложение (SPA) без бэкенда. Все уязвимости находятся в `devDependencies` (инструменты сборки: `vite`, `workbox`, `eslint`). Они используются только на этапе сборки и **не попадают в финальный бандл** (`dist/`), который получает пользователь. В браузере пользователя этот код не выполняется.

Вы можете убедиться в этом сами, запустив проверку только production-зависимостей:
```bash
npm audit --omit=dev
# Ожидаемый результат: found 0 vulnerabilities
```

Мы осознанно не используем `npm audit fix --force`, так как принудительное обновление ломает совместимость с `vite-plugin-pwa` (что приведёт к поломке сборки PWA и офлайн-режима).
